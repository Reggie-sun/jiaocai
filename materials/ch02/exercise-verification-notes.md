# Chapter 2 Exercise Verification Notes

## Scope and Method

An independent Python standard-library script derives the numeric and deterministic algorithm results from `exercise-inputs.json`. It covers E01–E06 and the separate Figure 2-5 route graph. It does not treat the answer manuscript as executable expected output: expected values in checks were reconstructed from the stated edge lists, rules, durations, data rows, constraints, and evaluation costs.

Small route graphs are checked by exhaustive simple-route enumeration. BFS, deterministic local greedy selection, and settled-node Dijkstra are implemented separately; nonnegative Dijkstra results are compared with the exhaustive minimum. E06 is checked with the augmented `(location, service_completed)` state, a service-time charge on first arrival at C, deadline pruning, and a second exhaustive enumeration that permits revisiting a location after the service-state change. DAG schedules use predecessor maxima and all source-to-sink chain sums. Classification metrics use exact rational arithmetic. Sorting uses Python's stable built-in sort with the specified keys.

## Limits

This is finite-data arithmetic and algorithm execution for the printed teaching inputs, not a general proof of an implementation for arbitrary graphs, data quality, human route safety, or real platform behavior. Exhaustive route enumeration is intentionally limited to the small supplied graphs. The automaton section verifies safe interpretation of result states only; no request was sent, and no external submission outcome was tested.
