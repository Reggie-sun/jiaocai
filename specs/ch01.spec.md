### Section 1.1

**计算思维的定义与内涵：超越编程**

预算：8000字；学习成果：LO1、LO2、LO3；先备：章首学习目标、基本表格与程序流程常识。

**案例：**原创教学情境：共享显示设备借用；先呈现含糊需求与冲突，再分析字段、条件、步骤和检验。

| 小节 | 内容 | 教学作用 |
| --- | --- | --- |
| 1.1.1 | 案例：设备够用，为什么仍会发生借用冲突 | 明确需求、缺失信息与冲突，案例分析形成待解决问题。 |
| 1.1.2 | 计算思维、编程、算法与工具使用 | 用正例和反例解释区别与联系，采用经核验的定义与作者工作性解释。 |
| 1.1.3 | 核心方法如何共同工作 | 概览抽象、分解、模式识别、算法、评估、自动化和泛化，说明相互配合及边界；不在此系统讲解第二章的算法选择。 |
| 1.1.4 | 从问题说明到可检验的处理过程 | 组织目标、输入、约束、输出、检查和迭代；借鉴样稿三层框架，明确其为本书教学组织方式。 |
| 1.1.5 | 思维训练：安排借用并检验资源变化 | 随任务交付数据、约束、参考解和检验；条件变化后重新判断可行性。 |

**反思：**追查遗漏的条件、表示的取舍和候选失败的原因；用过程证据说明修正。

**配套：**图1-1、图1-2、图1-3；E01。

**边界：**只建立方法轮廓和小规模检验，不讲算法复杂度证明、模型训练、API部署或工具连接器教程。

### Section 1.3

**计算思维的普适性与迁移条件**

预算：7500字；学习成果：LO2、LO5；先备：1.1。

**案例：**原创教学情境：将设备借用规则迁移到社区活动场地分配，加入人数、容量和不同资源要求。

| 小节 | 内容 | 教学作用 |
| --- | --- | --- |
| 1.3.1 | 案例：名字换了，规则还能照搬吗 | 保留问题结构并改变关键条件，制造有意义的迁移检验。 |
| 1.3.2 | 从表面相似到结构对应 | 对应目标、实体、关系、限制、步骤和评价，说明领域知识的作用。 |
| 1.3.3 | 表示和执行的适用条件 | 比较校园、公共服务与业务资料归类等情境，说明可表示性、信息质量和规则清晰度；用机械化、电气化、信息化、智能化的简短背景比较任务与工具变化，具体史实采用前核验，不写必然演化论。 |
| 1.3.4 | 模型边界与无法自动决定的问题 | 用公平、价值选择和因果解释的小例说明计算表示不能自行给出全部答案。 |
| 1.3.5 | 思维训练：保留共同结构并处理例外 | 提供新场景数据和映射任务，要求说明新增条件、反例和修改依据。 |

**反思：**迁移前确认了什么；哪些条件不能继承；反例如何改变判断。

**配套：**图1-5；E03。

**边界：**建立迁移入门，跨界创新策略和原型设计在第五章深化；不把院校定位等同于必须全用金融案例。

**与数学、实证、批判、设计和系统思维的互补**

| --- | --- | --- |

**反思：**采用的视角能回答什么，遗漏了什么；需要新增哪些证据。

**边界：**只解释互补关系与方法选择，后续章承担论证、创新、系统项目与技术责任的深入教学。

#### E01 Data

本向量为教学示例数据，类型 `synthetic_teaching_data`。各请求占一个完整时段；`display`表示显示功能。

| 时段 id | 顺序 order |
| --- | --- |
| S1 | 1 |
| S2 | 2 |
| S3 | 3 |

| 设备 id | capabilities | available_slots |
| --- | --- | --- |
| D1 | display | S1、S2、S3 |
| D2 | display | S2、S3 |

| 请求 id | required_capability | allowed_slots |
| --- | --- | --- |
| R1 | display | S1 |
| R2 | display | S1、S2 |
| R3 | display | S2、S3 |
| R4 | display | S2、S3 |

**硬约束：**

- 每个请求恰好安排一次，占一个完整时段
- 设备在该时段开放且具备所需功能
- 安排时段属于请求的allowed_slots
- 同一device_id、slot_id组合只能给一个请求

**偏好：**

- 可比较较早完成的安排，但不能为此违反硬约束，也不宣称唯一最优

| 变体 id | 变更 | 预期可行性 |
| --- | --- | --- |
| baseline | 无变更（change=null） | 可行（true） |
| D2_closed | device_id=D2，available_slots=[] | 不可行（false） |

输出request_id/device_id/slot_id三列；原条件至少一条可行解，变化后列出无解依据；参考解须再次逐项检查。

**实际核验：**枚举有限组合或等价程序检查原条件与D2_closed；记录运行输出，不能仅相信AI答案。

**评价维度：**条件完整；表示清楚；满足全部硬约束；明确可行/无解/协商提案；能够解释修正。
