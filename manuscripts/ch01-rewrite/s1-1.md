## 1.1 计算思维的定义与内涵：超越编程

你可能已经写过排序、搜索或数据处理程序，也能根据给定接口完成一个功能。但是，当题目变成“为大家安排共享设备，尽量方便一些”时，困难会转移：什么算安排完成，哪些条件必须同时成立，程序没有找到答案意味着什么？输入输出格式没有现成答案，需要由解决问题的人建立。一个能运行的程序，可以实现不完整的规则；一个没有写程序的分析，也可能准确揭示当前条件为什么无法满足。本节关心的是从现实描述到可检验解决过程之间的判断。

下面先看一项共享显示设备安排。我们将把同一情境分别表示为资源数量、可选关系和部分安排，比较它们能够支持的结论，再通过失败分支、瓶颈反例和接口单位问题，理解抽象、分解、模式识别与算法设计如何相互约束。读完后，你应能指出一个方案具体错在哪里，并判断修正应发生在选择、表示、规则还是现实条件上。

### 1.1.1 案例：每个请求都有位置，为什么仍然排不出来

一个虚构课程项目组需要协调两台共享显示设备。一天分为S1、S2、S3三个完整时段，D1三个时段都开放，D2仅在S2、S3开放。四条请求都需要显示功能：R1只能选S1，R2可以选S1或S2，R3、R4各可以选S2或S3。每条请求占一个完整时段，同一设备同一时段只能交给一条请求。这个情境及其数据均为本书教学示例，不代表学校的设备或管理制度。

第一位协调者只比较数量：两台设备、三个时段，似乎最多能服务六次，四条请求应当足够。这个算式忽略D2在S1没有开放，实际只有五个设备时段；进一步说，即使五个位置仍多于四条请求，也不能仅凭总量得到完整安排，因为某条请求可能无法使用那些空闲位置。资源有多少和资源是否可达，是两个不同问题。

第二位协调者为每条请求列出至少一个允许位置，认定“每条都能排”已经足够。如果把R1和R2都放到D1-S1，两行分别满足功能、开放和请求时段要求，合在一起却重复占用。同一行的合法性依赖该行的数据，整体的合法性还依赖行与行的关系。一个逐行检查而没有共享占用状态的程序，会准确检查前一种性质，却遗漏后一种性质。

第三位协调者按顺序先安排R2，选择D1-S1。轮到R1时，它没有剩余位置，于是宣布资源不足。这个结论比前两个看起来谨慎，但仍然错把当前选择的后果当成原问题的性质。撤销R2的选择，让它改用D1-S2，R1就能使用D1-S1。失败说明某条分支无法继续，未必说明所有分支都失败。

这三个判断分别丢掉了允许关系、共同占用和替代选择。它们可以发生在手工填表、电子表格、程序或AI生成中，工具名称不会改变错误的逻辑。问题分析的价值，正是找出结论依赖哪些信息，并检查当前表示是否足以保留这些信息。

把需求写成可以复查的约定，需要明确：四条请求都要完成，每条恰好安排一次；所选设备具备所需功能，设备与请求都允许该时段；设备时段不能重复使用。在这些条件满足后，可以讨论较早完成的偏好。“每组都满意”则还需要知道满意的口径，不能由请求编号或填表顺序代替确认。图1-1展示了从口头要求到检查关系的转化。

### 1.1.2 从写程序到解释解决过程

Wing在2006年的文章中倡议将计算思维视为广泛适用的能力，强调计算机科学的概念能够支持问题解决，而不能把这种思考缩减为编程[[S01]]。2010年的说明把一种问题与解法表述的定义归于Cuny、Snyder与Wing共同使用[[S02]]。两份文献提供概念背景；本章使用的教学组织方式，是为了帮助你解释具体任务，不将它冒称为唯一学术定义。

本书把计算思维工作性地理解为：围绕目标选择对象、关系和状态的表示，组织可执行或可推演的处理过程，并检查结果及其适用条件。这里有三项需要分开判断的工作：表示让什么差异可见，过程怎样操作这些差异，证据支持多强的结论。设备安排里，位置的可达性属于表示；选取与回退属于过程；一条完整合格安排或一个瓶颈计数属于证据。三者衔接时，别人才能重建你的判断。

算法解决的是规定输入范围内的一类处理问题。用回溯选择位置，可以构成一个有限搜索算法；用一份安排检查是否冲突，也可以构成一个检查算法。二者承担不同职责：生成器寻找答案，检查器判定给出的答案是否满足约定。会写检查器，不等于已经有高效的生成器；有一个生成器，也不保证它的输出一定合格。把这些职责混为一谈，会使你在“程序有输出”之后过早停止。

编程把步骤落实到某种执行语言。语言中的整数、集合和字典提供表示手段，但现实概念与这些类型之间仍需要映射。用字符串保存设备编号很常见，字符串相同是否表示同一实物，却要由数据契约回答。若一台设备登记为“会议屏A”和“D1”两个名字，程序可能把同一实物当成两台资源。类型合法只说明数据能被处理，身份一致才说明占用计算符合情境。

工具使用的成果也应放到这条关系中理解。AI可以把需求整理成字段，表格可以筛选候选，程序可以枚举组合。判断它们是否有帮助，要看它们保留了什么信息、执行了什么规则、留下什么可复查证据。流畅说明不能替代设备开放记录；自动枚举不能替代公平标准；精美表格不能替代唯一占用检查。工具改变成本和表达方式，但不会自动决定问题应该如何定义。

一个常见的误解是：越形式化，分析就越可靠。形式表达确实能暴露矛盾，却也会把遗漏固定下来。若把“R1只能S1”错误录入为“S1或S2”，搜索程序可能给出形式上完全合法的结果。你应当分别问，规则是否忠实于已经确认的要求，执行是否忠实于规则，结果在现实中是否可用。后两项不能反过来证明第一项；三种检查也不必由同一个工具完成。

计算思维因此可以与经验判断、协商和实证观察共同工作。一个要求暂时没有可计算的精确表达，不意味着它不重要；它可能需要先调查或讨论。把尚未确认的价值要求留在模型边界外，并说明它影响哪些结论，比随手赋一个权重更加准确。在1.4节中，我们将看到数学结果完全正确而现实效果仍需要进一步证据的情况。

### 1.1.3 抽象：保留会改变判断的差异

抽象的任务不是尽量删掉细节，而是选择足以完成当前判断的差异。设备颜色通常不影响本题的可行性，可以不进入模型；显示功能和开放时段影响候选，必须保留。判断一个字段是否必要，可以做一个思想实验：保持当前模型里的信息不变，只改变被省略的现实细节，结论会不会改变？如果会，当前表示可能把需要区分的两种情境合并了。

例如，只保存“设备D2今天开放”，没有记录具体时段，就会把只在S3开放和在S2、S3都开放视为一样。对R3是否能用D2-S2而言，两种情境的答案不同。省略时段不只是降低精度，它改变了我们能够回答的问题。反过来，如果任务只是统计今天至少开放过一次的设备数，这个布尔字段可能已经足够。表示的好坏必须相对于目标判断，不能单独按字段多少评价。

对本题，定义位置集合U={a,b,c,d,e}，其中a=D1-S1，b=D1-S2，c=D2-S2，d=D1-S3，e=D2-S3。设备身份和时段合成一个位置，是为了直接表达一次互斥使用。对请求r，D(r)表示满足功能、开放和请求时间要求的位置集合。具体候选见表1-X11a。

表1-X11a 讲解示例中的允许位置

| 请求 | 允许位置集合 | 决定集合的限制 |
| --- | --- | --- |
| R1 | {a} | 只能S1，D2在S1不开放 |
| R2 | {a,b,c} | 允许S1、S2 |

一份完整安排可以看作函数f，把每条请求映到一个位置。合格安排同时满足f(r)属于D(r)，以及不同请求对应不同位置。第一条表达每行合法，第二条表达整体不重复；函数定义域为全部请求，表达不能漏项。这种形式化没有要求你记住更多术语，而是把原先容易混在一起的三类条件分别显现出来。

这里将设备时段作为一个不可分位置，有明确假设：每条请求持续一个完整时段，每个位置容量为一，没有准备或搬运占用。如果请求持续两个时段，开始位置不同也可能重叠，函数的单射性质不再足够。1.3节会重建这种占用表示。先指出简化假设，有助于理解为什么一个模型可以准确处理当前题目，却需要在新情境下修改。

另一种抽象错误来自接口语义。NASA关于Mars Climate Orbiter损失的调查说明，地面软件输出的冲量数据使用英制单位，导航处理期望公制单位，单位失配未被及时发现[[S10]]。本章不把这项复杂事故归结为一个算式；我们只取其中可由原始记录支持的接口问题，分析“双方都收到一个数”为何不等于“双方理解的是同一个量”。

设一条单独的教学记录为5 lbf·s，采用约4.45的转换系数，应得到约22.25 N·s。这里的5是自拟数值，不是事故遥测。如果接收方直接把数字5读作N·s，格式解析可以成功，数值含义却改变了。只检查输入是浮点数，无法检验量的种类、单位和转换方向。把单位删掉形成“统一数值字段”，反而删除了接口正确性所需的信息。

你可以从这个例子区分表示一致和语义一致。两个模块都用相同字段名，不保证同一单位；两个模块都通过自己的局部测试，不保证连接后理解相同；转换程序能运行，不保证转换只发生一次或方向正确。有效的接口约定应说明量、单位、适用范围和转换责任，再用已知输入输出对检查它。例如5 lbf·s转约22.25 N·s，而已经是N·s的数据不应再次放大。这是领域含义进入程序检查的地方。

### 1.1.4 分解：局部合法怎样组成整体方案

把任务拆成请求筛选和位置选择，可以减少一次面对的复杂性，却不能切断两部分的关系。筛选得到D(r)，只保证每个候选单独可用；位置选择还要处理不同请求争用同一资源。分解后的接口不应只有“每个请求有几个候选”，还应传递“这些候选分别是谁”。否则候选数量相同而共享程度不同的两组任务，会被错误看成同一种情形。

先推演一条失败分支。安排R2到a，已经占用的位置为{a}。随后R1的候选只有a，与占用集合相交，不能加入。此时失败的是包含R2→a的部分安排。回退应撤销这一选择及其占用，再试R2→b；然后R1→a，R3→c，R4→d，可以组成完整方案。注意回退撤销的是选择，没有修改R1的时段，也没有让设备重复使用。

搜索可以维持一个不变量：当前已安排的请求各出现一次，每行属于对应候选集合，位置互不重复。加入一项选择前先检查它是否保持这一性质；回退后恢复进入该分支之前的状态。这个不变量保证部分解合法，但不保证一定可以扩展成完整解。R2→a本身合法，却阻挡R1；因此“已检查的部分都正确”仍然不能等同“整个任务必能完成”。

先处理候选少的请求，在本题里会先选R1，能避开这条失败分支。它是利用约束程度的策略，不是对所有任务无需回退的保证。假如两个同样灵活的请求都只能使用最后一个空位，早期顺序无法凭空增加位置；如果偏好要求优化总成本，找到第一条可行解也可能远未结束。策略价值应按减少搜索和满足目标的证据评价，不能因一次成功便称最优。

有些失败能用瓶颈直接证明。考虑任意一组请求A，它们合起来能够使用的位置数，必须至少等于这组请求数：|⋃D(r)|≥|A|，其中并集只对A中的请求取。理由是每条请求都要占据不同位置；若三条请求合起来只能使用两个位置，至少一条无处可放。这个计数是本模型下的必要条件，本章不展开完整匹配定理或证明。

现在给一个独立反例：T1、T2、T3都只能选b或c，资源表还列出d。每条请求候选非空，位置总数等于请求总数，仍然无解，因为d对它们不可达。把A取为这三条请求，允许位置并集只有两个。图1-2把无连接的位置放在瓶颈框外，帮助你区分“有资源”与“这组请求可以使用的资源”。

识别“若干请求共同争用不足的位置”，是模式识别在这里的具体作用。它没有按相同文字给请求分类，而是在关系结构中识别会改变可行性的特征。把请求换成其他名字，这个计数理由仍能成立；把一个位置改为可并行服务两条请求，理由就必须加入容量。模式能复用到哪里，取决于不重复占用这一假设是否保留。

分解还会暴露另一种错误：把同一实体交给两个子任务独立安排。如果甲组和乙组分别为自己的请求做出合格排程，但共用D1，合并结果可能冲突。解决办法不只是最终“看看有没有冲突”，还要明确共享状态由谁维护、哪个选择更新了它、发生冲突时哪项决定可以撤回。整体约束决定了子问题之间需要怎样的接口，而不是组织分工决定约束可以忽略。

### 1.1.5 算法、检查器与证据强度

在候选有限的题目里，可以按以下伪代码搜索。它意在暴露状态及停止条件，不作为大规模排程的推荐实现。未安排集合和已占用集合要随分支同时更新；回退必须撤销本分支加入的记录。

```text
search(remaining, used, partial):
    if remaining is empty:
        return a copy of partial
    r = choose one request from remaining
    for u in allowed[r]:
        if u not in used:
            add (r,u) to partial and u to used
            answer = search(remaining - {r}, used, partial)
            if answer exists: return answer
            remove (r,u) from partial and u from used
    return NO_SOLUTION_IN_THIS_BRANCH
```

为什么这个过程会结束？请求数量有限，递归每次减少一条未安排请求，每个候选集合也是有限的。为什么输出满足硬约束？每次加入检查候选归属与不重复，只有未安排集合为空时才返回。为什么一次分支返回失败不足以宣布原题无解？因为上层还有其他候选可尝试。只有所有分支按约定完整覆盖，才可以把顶层失败解释为该有限模型没有解。

这几个理由分别涉及终止、输出正确性和搜索覆盖。实际程序可能破坏其中某项：忘记撤销used会错误删掉后续候选；只试每条请求的第一个位置会漏解；发现一行合法就提前返回会漏请求。若只用一组恰巧成功的数据测试，三种错误都可能暂时不出现。理解算法应包含这些失败条件，而不是只描述成功流程。

检查器可以比生成器简单。给定一份安排，检查请求编号是否恰好覆盖全部请求，检查每行是否属于D(r)，再检查位置是否重复。一个重复位置反例、一份缺项表和一份非法时段表，各针对不同性质。还应加入一份合法表作为对照：检查器必须接受合格输入，不能只会拒绝错误。你可以手工完成这些检查，也可以把它们写成小程序。

不过，生成器与检查器如果同时沿用错误的D(r)，会共同接受不符合原始需求的答案。这是共享错误的风险：彼此独立的运行不等于彼此独立的依据。将候选构造对照原请求、将输出检验对照原硬约束，可以增加独立参照；已知单位转换值和最小冲突案例也可以避免两段代码只是相互复述。最终仍须说明检查覆盖哪些性质、哪些假设未被检验。

证据应和结论对应。给出一条完整安排并逐项检查，足以证明存在可行解；不用再遍历全部方案。宣称某个有限模型无解，需要覆盖全部候选，或给出足以否定所有方案的瓶颈理由。只运行到时间上限，应报告在当前预算内未找到；输入缺失，应报告尚不能判定。在1.2节中，我们还会区分这种有限无解与一般不可判定问题。

算法效率也取决于所要求的成果。只找任意可行解可以在找到第一条时停止；统计所有解需要继续遍历；选择最优解需要明确目标并说明比较覆盖。以“程序运行更快”评价方法时，先确认它们解决的是同一任务。一段只检查现成答案的程序，比寻找答案更快，不意味着它可以替代搜索。

### 1.1.6 人机协作中的分工与修改位置

AI可以帮助整理需求、列候选、解释失败或生成检查程序，但它的输出仍属于需要检验的材料。NIST的生成式AI风险资料讨论了自信而错误、虚构或偏离输入的输出风险[[S09]]。这里采用的是一般风险说明，不是对某个工具当前性能的测量，也不要求你开通特定服务。手工、表格和本地程序均可完成本节任务。

一个有用的协作请求应让任务边界显现，例如：“只使用所附设备、请求和时段，不添加资源，不改变允许时段；先给候选安排，再列每项硬约束的检查依据；无法确认的条件单列。”这有助于组织输出，但提示本身不能证明模型遵守要求。你仍要对照数据检查，而且要警惕解释与表格不一致：文字说没有重复，表中却可能出现相同位置。

发现错误后，先决定修改什么。若输出把两条请求放在同一位置，规则没有问题，候选或实现需要修正；若请求的连续占用根本未表达，单改一行可能掩盖模型问题；若全部合法候选已被穷尽而无解，应讨论现实条件是否允许协商。让AI“再给一版”只有在错误类型明确时才有目标，否则可能只是换一个表面流畅的答案。

图1-3用三条返回路径表示这种区别。检查失败不必总回到同一环节：选择错误返回选择，规则或表示不足返回模型，信息不清返回需求。每次修改都要重新核对受到影响的结论。改变设备开放时段会影响候选和可行性；仅修正说明文字不会凭空改变一个非法安排。

保留一份足够复查的记录，比保留所有对话更有价值。记录当前数据版本、采用的规则、候选、检查结论和修改依据，就能说明答案对哪些条件成立。不同尝试之间若偷偷改变条件，则不能把成功归因于搜索策略改善。将“新增时段后找到安排”写成“原问题终于解决”，会让学习者误判方法能力和资源需求。

**本节反思。**在自己的记录中找一处“模型看不见的差异”和一处“局部合法却不能继续的选择”。前者需要补什么表示，后者需要撤销什么状态？再说明哪条证据足以证明存在方案，哪条证据只能说明一次尝试失败。把反思写成可以定位的例子，会比罗列方法名称更能展示你对解决过程的理解。
