# Chapter 2 Implementation Plan

## Goal

依据[第二章Spec](../specs/ch02.spec.md)完成第二章完整教材和正式Word/PDF，验证现有生产体系在不同知识结构下的复用。

## Contracts and Invariants

Native Codex拥有本轮lifecycle；SDD以Markdown Spec/Plan维护内容契约，Multi-Agent只承担互斥写作与真实独立审校。蓝图五节与整章篇幅不变；复用`textbook-style-v1.0`和DOTX，Harness CLI/schema不改。原两份Word、第一章、历史证据与模板保护。正文源、合并稿、图、数据、答案和排版必须一致；reviewer不能代替Parent验收。

## File Ownership

writer A：`manuscripts/ch02/s2-2.md`、`s2-3.md`、`answers-e02.md`、`answers-e03.md`。writer B：`manuscripts/ch02/s2-4.md`、`answers-e04.md`。Parent：其他新`ch02`文件、`specs/ch02.spec.md`、本Plan、`runs/ch02.*.json`、目的记录；writers完成后Parent才能接管其文件。独立审校read-only，报告由Parent保存。

## Verification and Recovery

`python3 -m unittest discover -s tests -v`、`python3 scripts/harness.py validate`验证旧工程；`materials/ch02/verify_exercises.py`复算本章数据；`prepare.py`生成合并稿并核对引用/篇幅；`build_docx.py`和`verify_layout.py`为本章适配，不成为第二套全书格式owner。`render_docx.py`生成实际页图，页面阅读记录哈希和覆盖范围。独立reviewer实质修改后读新快照；source冻结期间Parent只动frozen set外文件。故障按SUBAGENTS/Skill保留原结果，非阻断优化不暂停生产。

## Self-Review

M1—M6覆盖A1—A7。边界包括内容、来源、练习、独立性、格式、工程状态和复用评估；顺序保证审校前内容稳定、验收前实际页面稳定。不存在模板重设、全书重构、worktree或多余approval步骤。

## Bounded Recovery

三次Kimi真实attempt均未形成可用完整报告，预算保留并结束。按Spec的Bounded Recovery Amendment，由一个新Native reviewer_high独立完整接手专业Scope，一次初审及最多两次必要复查；不新增第四次Kimi，不让原教学审校者改名承担第二角色。原manuscript数据和页面快照保持；新Spec/Plan hash、profile、会话ID与观察证据另行绑定，不追改旧seal或receipt。
